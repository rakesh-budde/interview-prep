# Kubernetes Interview Preparation Prompt - FAANG Level (>50 LPA)

## Objective
Generate a comprehensive, production-grade Kubernetes interview preparation guide covering:
- Deep system internals (how Kubernetes works under the hood)
- Architecture patterns for scale (1000+ nodes, 50,000+ pods)
- Real troubleshooting scenarios from production environments
- Hands-on exercises with step-by-step solutions
- Design questions for senior/principal engineer interviews

## Target Audience
- Senior DevOps Engineers (5+ years)
- Site Reliability Engineers (SRE)
- Platform Engineers
- Cloud Infrastructure Engineers
- Targeting FAANG/MANGA companies with compensation >50 LPA

---

## SECTION 1: CONTROL PLANE INTERNALS (25% of questions)

### 1.1 API Server Deep Dive
Cover these topics with system-level depth:

**Request Flow Analysis:**
- Complete request lifecycle: Authentication → Authorization → Admission → Validation → etcd
- Admission controller types: Mutating vs Validating webhooks
- API aggregation layer and custom API servers
- Watch mechanism and informer pattern (how clients stay in sync)
- API priority and fairness (APF) - rate limiting requests
- Audit logging configuration and analysis

**Interview Questions to Include:**
- "Walk me through what happens when you run `kubectl apply -f deployment.yaml`"
- "How does the API server handle 10,000 concurrent watch connections?"
- "Design an admission webhook that enforces resource quotas"
- "Explain the difference between optimistic and pessimistic concurrency in K8s"

**Hands-on Exercise:**
- Set up custom admission webhook from scratch
- Analyze API server audit logs to debug permission issues
- Configure API priority and fairness for multi-tenant cluster

---

### 1.2 etcd Deep Dive
Cover at system internals level:

**Raft Consensus Protocol:**
- Leader election process with timing diagrams
- Log replication and committed entries
- Quorum requirements (why 3/5/7 nodes?)
- Split-brain scenarios and resolution
- etcd performance tuning (disk IOPS, network latency)

**Data Storage:**
- How Kubernetes objects are stored in etcd (key structure)
- etcd compaction and defragmentation
- Backup strategies (snapshot vs continuous backup)
- Disaster recovery procedures

**Interview Questions:**
- "Your etcd cluster has 2 of 3 nodes down. What happens? How do you recover?"
- "etcd is consuming 100GB disk. How do you investigate and fix?"
- "Design etcd backup strategy for 99.99% availability"
- "Explain etcd MVCC and how it affects Kubernetes watches"

**Hands-on Exercise:**
- Perform etcd backup and restore on running cluster
- Simulate etcd leader failure and observe recovery
- Use etcdctl to directly query cluster state

---

### 1.3 Scheduler Deep Dive
Cover algorithm and extension:

**Scheduling Algorithm:**
- Filtering phase: Which nodes can run this pod?
- Scoring phase: Which node is best?
- Default predicates and priorities
- Resource calculation (requests vs limits)
- Node affinity, pod affinity, anti-affinity
- Taints and tolerations internals

**Advanced Scheduling:**
- Custom schedulers and multi-scheduler setup
- Scheduler extenders and webhooks
- Descheduler for rebalancing
- Gang scheduling for ML workloads
- Topology-aware scheduling

**Interview Questions:**
- "Pod is Pending for 10 minutes. Walk through your debugging process"
- "Design scheduling for ML training jobs requiring 8 GPUs together"
- "How would you implement bin-packing vs spreading across nodes?"
- "Explain scheduler preemption - when and how does it work?"

**Hands-on Exercise:**
- Write custom scheduler extender
- Configure pod topology spread constraints
- Debug scheduling failures with `kubectl describe` and scheduler logs

---

### 1.4 Controller Manager Deep Dive
Cover reconciliation patterns:

**Controller Pattern:**
- Informer/SharedInformer architecture
- Work queue and rate limiting
- Level-triggered vs edge-triggered reconciliation
- Leader election for HA
- Custom controller development patterns

**Built-in Controllers:**
- Deployment controller: Rolling update algorithm
- ReplicaSet controller: Pod counting and reconciliation
- StatefulSet controller: Ordered pod management
- Job/CronJob controller: Completion tracking
- Namespace controller: Finalizers and cleanup

**Interview Questions:**
- "A Deployment is stuck at 50% rollout. Debug it"
- "Explain how StatefulSet maintains pod identity during updates"
- "Design a controller that auto-scales based on custom metrics"
- "What happens if controller-manager crashes during a rollout?"

**Hands-on Exercise:**
- Write custom controller using client-go
- Implement leader election in your controller
- Debug stuck Deployment rollouts

## SECTION 2: NETWORKING DEEP DIVE (20% of questions)

### 2.1 CNI (Container Network Interface)
Cover implementation details:

**CNI Specification:**
- CNI plugin lifecycle (ADD/DEL/CHECK)
- Network namespace setup
- IP Address Management (IPAM)
- CNI chaining for multiple plugins

**Popular CNI Plugins:**
- Calico: BGP routing, network policies, eBPF dataplane
- Cilium: eBPF-based networking, observability, security
- Flannel: Simple overlay networking (VXLAN)
- AWS VPC CNI: Native VPC networking
- Azure CNI: Azure VNet integration

**Interview Questions:**
- "Compare Calico vs Cilium - when would you choose each?"
- "Pod can't reach another pod. Walk through network debugging"
- "Design CNI for 10,000 node cluster with multiple availability zones"
- "Explain how eBPF improves Kubernetes networking"

**Hands-on Exercise:**
- Deploy and compare Calico vs Cilium
- Debug pod-to-pod connectivity issues
- Analyze network policies with `calicoctl` or `cilium` CLI

---

### 2.2 Service Networking
Cover kube-proxy modes and alternatives:

**kube-proxy Modes:**
- iptables mode: Rule generation and performance
- IPVS mode: When to use, configuration
- eBPF mode (Cilium): Direct routing

**Service Types:**
- ClusterIP: Internal load balancing
- NodePort: External access via node ports
- LoadBalancer: Cloud integration
- ExternalName: DNS CNAME
- Headless services: Direct pod access

**Interview Questions:**
- "Explain the complete packet flow from client to pod via ClusterIP"
- "Service returns 5xx intermittently. Debug it"
- "Design service mesh for 500 microservices"
- "Compare kube-proxy iptables vs IPVS for 10,000 services"

**Hands-on Exercise:**
- Trace packet flow using `tcpdump` and `iptables -L`
- Configure IPVS mode and compare performance
- Debug service endpoint issues

## SECTION 8: TROUBLESHOOTING SCENARIOS (15% of questions)

### Critical Production Scenarios

Include 20+ detailed troubleshooting scenarios:

1. **Pod stuck in Pending** - Resource issues, affinity, taints
2. **Pod stuck in Terminating** - Finalizers, PDB, zombie processes
3. **CrashLoopBackOff** - Application errors, missing config
4. **ImagePullBackOff** - Registry auth, image not found
5. **OOMKilled** - Memory leaks, resource limits
6. **Evicted pods** - Node pressure, priority
7. **Service not reachable** - Endpoints, network policies
8. **DNS resolution failures** - CoreDNS issues
9. **Slow pod startup** - Image size, init containers
10. **Node NotReady** - Kubelet issues, disk pressure
11. **etcd leader election loops** - Network issues
12. **API server timeouts** - Resource exhaustion
13. **Certificate expiration** - Kubeadm certificates
14. **PVC stuck in Pending** - Storage class, provisioner
15. **Ingress not routing** - Controller, annotations
16. **HPA not scaling** - Metrics server, thresholds
17. **StatefulSet stuck during update** - Partition, PDB
18. **Job never completes** - Backoff limit, parallelism
19. **Secret not mounted** - ServiceAccount, RBAC
20. **Network policy blocking traffic** - Policy debugging

For each scenario include:
- Symptoms and error messages
- Step-by-step debugging commands
- Root cause analysis
- Fix and prevention
